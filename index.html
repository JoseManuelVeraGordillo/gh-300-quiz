GUÍA DE ESTUDIO · GH-300

Empezando con GitHub Copilot

Copilot acelera tareas de desarrollo, pero sus sugerencias necesitan contexto, revisión y validación humana.

La idea central

GitHub Copilot es un asistente de programación con IA integrado en el flujo de desarrollo. Puede proponer código, responder preguntas, explicar o refactorizar fragmentos y ayudar con pruebas y documentación. No conoce por completo tus requisitos ni sustituye el criterio del desarrollador: revisa cada resultado antes de incorporarlo.

01

Formas de trabajar

  • Sugerencias en el editor: aparecen como texto fantasma mientras escribes; acepta solo lo que te sirva.
  • Chat: permite preguntar, explorar código y pedir ayuda con tareas del proyecto.
  • Chat en línea: trabaja sobre el código seleccionado para explicar o proponer una edición concreta.
  • Los comentarios, el código abierto y la documentación aportan contexto a las sugerencias.
02

Capacidades y límites

  • Puede ayudar a: completar o generar código, explicar, refactorizar, proponer pruebas y revisar posibles mejoras.
  • No garantiza: que el código sea correcto, completo, seguro, eficiente o adecuado a la lógica de negocio.
  • Puede ignorar contexto importante, proponer patrones obsoletos o inseguros y rendir peor en tecnologías poco comunes.
  • Trátalo como asistente colaborativo, no como piloto automático ni sustituto de una revisión técnica.
03

Riesgos y uso responsable

Estudia los seis principios de IA responsable:

  • Equidad
  • Fiabilidad y seguridad
  • Privacidad y confianza
  • Inclusión
  • Transparencia
  • Responsabilidad

Ten presentes el sesgo, las vulnerabilidades, los secretos expuestos y las cuestiones de licencias o propiedad intelectual. La persona que integra el código sigue siendo responsable de revisarlo.

04

Validar antes de integrar

  • Revisa lógica, requisitos, seguridad, rendimiento y licencias; busca credenciales o secretos.
  • Ejecuta pruebas unitarias y de integración; define casos esperados antes de generar código cuando sea posible.
  • Aplica análisis estático y linters; considera fuzzing y escáneres de seguridad.
  • Observa registros y comportamiento en ejecución después del despliegue.
  • Usa control de versiones para revisar diferencias y volver a una versión anterior si es necesario.
05

Mejorar las sugerencias

  • Escribe instrucciones específicas e incluye objetivo, contexto, restricciones y ejemplos de estilo.
  • Refina el prompt de forma iterativa si la primera respuesta no cumple lo que necesitas.
  • Mantén el código y la documentación claros; los archivos enfocados facilitan aportar contexto relevante.
  • Revisa las dependencias externas y aplica las normas del proyecto y del equipo.
06

Instalación y solución de problemas

  • Instala VS Code y la extensión oficial de GitHub Copilot; inicia sesión con una cuenta que tenga acceso.
  • Si no conecta, comprueba Internet, proxy, red y posibles restricciones corporativas.
  • Si falla la autenticación, vuelve a iniciar sesión o renueva la autorización.
  • Si faltan archivos en el contexto, revisa exclusiones de Copilot, políticas y configuraciones del repositorio.
  • Actualiza VS Code y las extensiones, comprueba el acceso al plan y consulta los registros o límites de uso.

La interfaz y los pasos cambian entre versiones. Confirma los detalles en la documentación vigente de GitHub y VS Code.

Para responder preguntas

Recuerda la diferencia entre sugerir y garantizar: Copilot propone; el desarrollador verifica. Relaciona cada riesgo con una mitigación y memoriza los seis principios de IA responsable.

La idea central

La privacidad de Copilot depende de una combinación de plan, configuración personal, políticas de la organización y contexto compartido con el editor. Protege los datos sensibles antes de pedir ayuda y revisa las sugerencias: los filtros y las exclusiones reducen riesgos, pero no sustituyen la seguridad del repositorio ni el criterio humano.

01

Planes y tratamiento de datos

  • El material distingue planes individuales (Free, Pro y Pro+) y organizativos (Business y Enterprise); las funciones y controles varían entre planes.
  • En cuentas individuales, revisa los controles de sugerencias que coinciden con código público y las opciones de uso de datos para entrenamiento.
  • En organizaciones puede haber políticas y administración centralizadas sobre modelos, datos y acceso.
  • No infieras el uso o retención de datos solo por el nombre del plan: consulta los ajustes de tu cuenta, el contrato y la política vigentes.
02

Configuración e instrucciones

  • El editor puede permitir habilitar o deshabilitar Copilot en general o por lenguaje; una opción específica puede prevalecer sobre la general.
  • Los ajustes del usuario, del espacio de trabajo y las políticas de organización pueden tener distinto alcance o prioridad.
  • Las instrucciones del repositorio orientan el estilo y el contexto de las respuestas; no equivalen a una política de privacidad ni a una exclusión de contenido.
  • Comprueba el nombre y la ubicación de cada ajuste en la documentación de la versión que utilizas.
03

Exclusiones de contenido

  • Las exclusiones buscan impedir que rutas o archivos seleccionados se usen como contexto para sugerencias.
  • Úsalas para reducir la exposición de secretos, credenciales, datos personales y código confidencial; evita compartirlos directamente en prompts.
  • La configuración disponible y quién puede administrarla dependen del producto, el plan y las políticas de la organización.
  • Las referencias desde archivos permitidos, enlaces simbólicos, perfiles o contextos remotos pueden complicar el alcance: valida la configuración y sus límites.
04

Propiedad intelectual y contratos

  • Que una sugerencia sea generada por IA no elimina la obligación de comprobar licencias, derechos de terceros y normas aplicables.
  • Los filtros de coincidencia con código público pueden reducir ciertos riesgos; no garantizan que una sugerencia esté libre de reclamaciones.
  • Las garantías, indemnizaciones y responsabilidades dependen del plan, los términos aplicables y el uso de los controles requeridos.
  • Antes de aceptar una protección contractual como garantía, consulta el contrato vigente o al equipo legal.
05

Controles de seguridad

  • El filtro de coincidencias con código público trata coincidencias públicas; no debe confundirse con un análisis de duplicados del código privado de tu organización.
  • Copilot no reemplaza las herramientas de seguridad del repositorio. Complementa el flujo con revisión, pruebas y análisis estático.
  • Dependabot ayuda a gestionar dependencias vulnerables; code scanning busca vulnerabilidades en el código y secret scanning detecta secretos expuestos, según la configuración y el plan.
  • Configura permisos y políticas organizativas con el principio de menor privilegio.
06

Diagnóstico de exclusiones y sugerencias

  • Comprueba si Copilot está habilitado para el lenguaje y el ámbito correctos; revisa también las políticas y el acceso al plan.
  • Verifica exclusiones en el perfil, el espacio de trabajo o el contexto remoto donde realmente trabajas; revisa errores y registros.
  • Tras cambiar ajustes, actualiza o reinicia el editor y las extensiones si la documentación lo recomienda.
  • Si una sugerencia parece insegura, incorrecta o basada en contenido excluido, no la aceptes: conserva el contexto necesario para investigar sin exponer datos sensibles.

Para responder preguntas

Distingue el filtro de código público de las exclusiones de contenido; separa instrucciones del editor de controles de privacidad; y recuerda que Copilot no detecta duplicados internos ni ofrece garantías legales automáticas.

Planes, políticas de datos, nombres de ajustes y mecanismos de exclusión cambian con el tiempo. Contrasta los detalles concretos con la documentación y los términos actuales de GitHub Copilot.
